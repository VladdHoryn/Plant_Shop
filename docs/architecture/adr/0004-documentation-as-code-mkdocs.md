# ADR-0004: Документація як код — MkDocs Material з публікацією на GitHub Pages

| Поле | Значення |
|---|---|
| Номер | 0004 |
| Статус | **Proposed** |
| Дата рішення | 2026-11-22 |
| Автор / власник | VladdHoryn |
| Зачіпає | `docs/`, `mkdocs.yml`, `overrides/`, `tools/mkdocs/`, `.github/workflows/docs.yml`, `.github/CODEOWNERS` |
| Пов'язані | [ADR-0005](0005-api-first-openapi-contract.md) — контракт API рендериться на сайті |

## Контекст

Після ЛР№10 знання про систему — Markdown у репозиторії (SDD, ISD, ADR), але без збірки й публікації: мертве
посилання чи сторінку, на яку ніщо не веде, ніхто не помічає; README розрісся до 500 рядків і змішував
аудиторії; власник і дата перегляду документа жили в окремій таблиці регламенту, далеко від самого документа.

## Розглянуті альтернативи

| Варіант | Переваги | Недоліки |
|---|---|---|
| A. Лишити Markdown у Git без збірки | нуль інструментів | дефекти документації не зупиняють злиття; немає пошуку і навігації |
| B. **MkDocs Material + GitHub Pages** | Markdown лишається джерелом (працює в GitHub, Obsidian, Notion); strict-збірка ламається на мертвих посиланнях і сторінках поза nav; пошук українською; плагіни для Mermaid, Swagger UI, дат з Git | потрібен Python-інструментарій (вирішено Docker-образом `tools/mkdocs`) |
| C. Docusaurus | React-компоненти, версіонування з коробки | Node.js-стек, MDX замість чистого Markdown — гірше для Obsidian/Notion |
| D. Вікі (Confluence / GitHub Wiki) | редагування в браузері | окремо від коду: немає рев'ю в PR, немає CI-перевірок, дрейф гарантований |

## Рішення

Варіант **B**. Правила, що з нього випливають:

- `docs/` — джерело бази знань; сайт лише рендерить його. Документація процесу (звіти лабораторних) лишається в
  Git, але виключена зі збірки (`exclude_docs`).
- Збірка завжди `--strict` з `validation` на `warn` для посилань, якорів і сторінок поза nav: будь-яке
  попередження = Exit Code 1 = сайт не публікується.
- Кожна сторінка має front matter-паспорт `owner` / `status` / `review_date` / `tags`; шаблон `overrides/main.html`
  показує його на сайті, CI-аудит рахує прострочені `review_date`.
- Посилання між документами — звичайні відносні Markdown-посилання (не `[[wikilinks]]`): їх перевіряє
  strict-збірка, і так само їх показує граф Obsidian.
- Версії інструментів закріплені (`tools/mkdocs/requirements.txt`) і спільні для локальної збірки і CI.

## Наслідки

- **Позитивні:** дефект документації зупиняє доставку так само, як червоний тест; одна правда для GitHub,
  Obsidian і сайту; дата останньої зміни кожної сторінки береться з Git, а не пишеться вручну.
- **Негативні:** ще один обов'язковий job у CI; перенесення файлів змінює адреси — старі адреси лишаються
  заглушками зі `status: deprecated`.
- **Умова прийняття:** перший зелений конвеєр `docs.yml` з публікацією сайту; після нього статус — Accepted.
