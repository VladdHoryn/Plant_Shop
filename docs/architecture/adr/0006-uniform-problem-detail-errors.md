# ADR-0006: Єдиний формат помилок RFC 9457 для всіх відповідей, включно з помилками фреймворку

| Поле | Значення |
|---|---|
| Номер | 0006 |
| Статус | **Proposed** |
| Дата пропозиції | 2026-11-22 |
| Автор / власник | VladdHoryn |
| Зачіпає | `GlobalExceptionHandler` усіх сервісів, api-gateway, схема `Error` у `docs/api/openapi.yaml` |
| Пов'язані | [ADR-0005](0005-api-first-openapi-contract.md) — розбіжність знайдена під час опису контракту |

## Контекст

Під час опису контракту (ADR-0005) з'ясувалося, що сервіси повертають помилки у **двох** форматах. Помилки, які
обробляє `GlobalExceptionHandler` (404, 409, валідація тіла, 503 Feign), — RFC 9457 Problem Details
(`application/problem+json`). Помилки, які формує сам Spring (зламаний JSON, неправильний тип чи відсутній
параметр, непередбачена помилка 500), і помилки gateway (немає живого екземпляра) — формат Spring Boot
`{timestamp, status, error, path}` (`application/json`). Тому контракт 1.0.0 описує один об'єкт `Error` зі
спільним обов'язковим полем `status` і двома наборами необов'язкових полів.

## Розглянуті альтернативи

| Варіант | Переваги | Недоліки |
|---|---|---|
| A. Лишити як є, задокументувати обидва формати | нуль змін коду, контракт чесний | клієнт обробляє два формати |
| B. `spring.mvc.problemdetails.enabled: true` | одна властивість | вбудований обробник має `@Order(0)` і перехоплює валідацію раніше за наш, тобто губиться поле `errors` — зміна поведінки |
| C. `GlobalExceptionHandler extends ResponseEntityExceptionHandler` + обробник `Exception` → 500 у кожному сервісі; `ErrorWebExceptionHandler` у gateway | один формат для всіх кодів | зміна коду 6 модулів і тестів; потрібна нова MAJOR-версія контракту (звуження схеми `Error`) |

## Пропозиція

Варіант **C** у наступному релізі API (2.0.0). До ухвалення діє варіант A: контракт 1.0.0 чесно описує обидва
формати, contract-тест перевіряє відповідність.

## Наслідки (якщо буде ухвалено)

- Схема `Error` звужується до RFC 9457 (обов'язкові `type`, `title`, `status`), `info.version` → 2.0.0, запис у
  CHANGELOG, тег документації `docs-v3.0`.
- Цей запис отримає статус Accepted; якщо буде обрано інший варіант — новий ADR, а цей — `Rejected`.
