## 1. Головне правило

> **Зміна коду = зміна документації.** Жодне злиття в `master` не проходить, якщо змінено поведінку, контракт,
> компонент або розгортання, а зачеплені документи не оновлено в тому самому pull request.

Правило забезпечується трьома рівнями:

| Рівень | Що перевіряє | Як |
|---|---|---|
| Автоматично в CI | кожен REST-ендпоінт контролерів є в SDD (розділ 5); кожен публічний `/api/**` — у README; `depends_on` кожного контейнера `docker-compose.yml` збігається з таблицею запуску ISD (розділ 5) | job `doc-drift` у `.github/workflows/docs-currency.yml` → `./scripts/doc-drift-check.sh`; червоний job блокує злиття |
| Звіт у CI | вік документів і кількість комітів коду після останнього оновлення документа | `./scripts/doc-currency.sh` → GitHub Step Summary |
| Людина (рецензент PR) | усе, що скрипт не бачить: зміст опису, діаграми, ADR, RTO/RPO | чекліст `.github/pull_request_template.md` |

## 2. Документи паспорта: власники і цикли перегляду

застарілий. Тому експлуатаційна документація переглядається щонайменше раз на 90 днів, архітектурна — раз на
180 днів. Перегляд = звірити документ з кодом, виправити розбіжності, оновити рядок «Останній перегляд» у
документі і в цій таблиці.

Заступник власника (backup owner) для всіх документів: **вакантно** — це single point of knowledge, див.
`docs/handover.md`, розділ Bus Factor.

Звіти лабораторних (`docs/*-report.md`, `docs/lab-*.md`, `docs/reports/`, `FINANCIAL_LEDGER.md`) — документація
процесу: вони фіксують факт у часі, не мають циклу перегляду і не оновлюються. Якщо такий звіт вводить в оману
щодо поточної системи, він позначається банером `DEPRECATED` з посиланням на актуальний документ (так зроблено
для `docs/k8s-report.md` і `docs/helm-report.md`).

## 3. Що оновлювати при зміні коду

| Змінено в коді | Оновити |
|---|---|
| `*/controller/*.java` (новий, перейменований, видалений ендпоінт, змінений формат відповіді) | SDD 5.1/5.2; README «API at a glance» для `/api/**`; README «What it does», якщо змінилась поведінка для користувача |
| `*/client/*.java` (новий Feign-клієнт, нова синхронна залежність) | SDD 2 (C4: стрілка), SDD 3 (залежності компонента); ISD 5, якщо змінився порядок запуску |
| `*/event/*`, `spring.json.type.mapping` | SDD 2.1, SDD 5.3; ADR-0002, якщо змінюється стиль інтеграції (новий ADR) |
| `*/db/migration/V*.sql` | SDD 4 |
| новий модуль / сервіс | SDD 2, 3, 4, 5; ISD 1, 3, 4, 5; README (таблиця сервісів, API); `doc-map.txt` аудиту |
| `docker-compose.yml`, `Dockerfile`, `k8s/`, `helm/` | ISD 1, 3, 5, 7, 8 |

| архітектурне рішення змінено | новий ADR з новим номером; старий — статус `Superseded by ADR-NNNN` |

## 4. Процедура перегляду

1. `./scripts/doc-drift-check.sh` — має бути `RESULT: PASS`.
2. `./scripts/doc-currency.sh` — для кожного документа паспорта «Age» не більший за цикл, «Lag» = 0 або всі
   коміти з «Lag» не зачіпають описане в документі.
3. Прочитати документ і звірити твердження з кодом (зразок — `docs/lab-10/claim-verification.txt`).
4. Оновити «Останній перегляд» у документі та в таблиці розділу 2 цього регламенту; закомітити як
   `docs(maintenance): review <документ>`.
